# Harmonic oscillator

**No simulation data:** train only on the ODE and prescribed initial
conditions; compare only with analytical $\cos x$ and its derivatives.
Exact interior values never enter training. Check $f(\pi)=-1$ and energy
$(f'^2+f^2)/2=1/2$. Accept order 2 before higher derivative constraints;
see the [staged validation gate and source notes](../validation.md).

## Problem

Find $f$ on the training interval $[-\pi,\pi]$:

$$
f''(x)+f(x)=0,\qquad f(0)=1,\qquad f'(0)=0.
$$

Exact solution: $f(x)=\cos(x)$. The initial value and initial slope fix both
coefficients in $A\cos(x)+B\sin(x)$.

## Run

After [setup](README.md#install), run:

```bash
uv run learnpdes train cosinus --epochs 5000 --points 64
```

`cosinus` names this scenario. Training samples 64 coordinates on `[-π, π]`, plus $x=0$.
The network uses smooth `Tanh` activations for second derivatives.

![Harmonic oscillator PINN training](../../assets/examples/cosinus/training.gif)

Recorded run; not regenerated by this command. Export a new interactive plot with
`uv run learnpdes train cosinus --no-gif`.
New plots cover `[-3π, 3π]`, shade the training interval, and label π multiples
with their decimal values (`π ≈ 3.141593`).

## Loss

Differentiate the network twice, then penalize the residual, value and slope:

$$
\mathcal L =
3\,\operatorname{mean}\big[(f_\theta''+f_\theta)^2\big]
+(f_\theta(0)-1)^2+(f_\theta'(0))^2.
$$

Save as `inspect_loss.py` in the repo root; run `uv run python inspect_loss.py`.

```python
import torch
from learnpdes.training import build_problem

torch.manual_seed(0)
model, problem, _ = build_problem('cosinus', points=64)
f = model(problem.inputs)
df = problem.partial_derivative(f, problem.x)
d2f = problem.partial_derivative(df, problem.x)

physics = (d2f + f).square().mean()
value = (f[problem.zero_mask] - 1).square().mean()
slope = df[problem.zero_mask].square().mean()
loss = 3 * physics + value + slope

reference, *_ = problem.get_loss('cosinus')()
torch.testing.assert_close(loss, reference)
print('Value:', value.item(), 'Slope:', slope.item())
```

The [derivative helper](../../learnpdes/model/objectives.py) uses `create_graph=True`
to differentiate twice and train through the residual. Keep gradients enabled.
Both initial conditions are soft penalties, not exact guarantees.

## Check

The runner compares against $\cos(x)$ on a separate 601-point grid over
`[-3π, 3π]`, reporting RMSE, maximum error and relative L2 error on that full interval.
It also reports these MSEs:

| Metric | Evaluation coordinates |
| --- | --- |
| Inside | $|x|\leq\pi$ |
| Outside to 2π | $\pi<|x|\leq2\pi$ |
| Outside to 3π | $\pi<|x|\leq3\pi$ |
| Far band | $2\pi<|x|\leq3\pi$ |
| Full ±2π | $|x|\leq2\pi$ |
| Full ±3π | $|x|\leq3\pi$ |

The far-band metric isolates the newly added region. The existing ±2π metrics
keep their original definitions. These evaluation losses never enter training.
Check value and slope losses if
amplitude or phase is wrong. Compare `--epochs`, `--points` and `--seed`;
low residual alone does not guarantee accuracy.

Keep the `cosinus` scenario and select a maximum even derivative order.
Each added order retains all previous constraints:

| Maximum order | Added equation | Added initial condition |
| --- | --- | --- |
| 2 (baseline) | $f''+f=0$ | $f(0)=1$, $f'(0)=0$ |
| 4 | $f^{(4)}+f''=0$ | $f^{(4)}(0)=1$ |
| 6 | $f^{(6)}+f^{(4)}=0$ | $f^{(6)}(0)=-1$ |
| 8 | $f^{(8)}+f^{(6)}=0$ | $f^{(8)}(0)=1$ |
| 10 | $f^{(10)}+f^{(8)}=0$ | $f^{(10)}(0)=-1$ |
| 12 | $f^{(12)}+f^{(10)}=0$ | $f^{(12)}(0)=1$ |
| $2k\geq4$ | $f^{(2k)}+f^{(2k-2)}=0$ | $f^{(2k)}(0)=(-1)^k$ |

The objective sums residual MSEs with weight 3 each and initial-condition
penalties with weight 1 each, all on the original training points. No extra
$f''(0)$ penalty is added. Compare evaluation MSE across orders, since their
total training losses contain different numbers of terms.

```bash
# One run, with cumulative constraints through order 6

uv run learnpdes compare-cosinus --epochs 25000 --seeds 0 --seeds 1 --seeds 2
```

The added equations already follow from the original ODE for an exact smooth
solution. They penalize additional derivative errors during finite training,

multiple seeds to see whether they help, without hiding poor extrapolation
behind a good fit inside the training interval.
